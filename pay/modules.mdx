# Pay modules

| Module | Path | Description |
| --- | --- | --- |
| Wallets | `/api/v1/payments/wallets` | Create and manage wallets |
| Transactions | `/api/v1/payments/transactions` | CREDIT / DEBIT processing |
| Checkout sessions | `/api/v1/payments/checkout-sessions` | Hosted checkout and payment links |
| Payouts | `/api/v1/payments/payouts` | Bank payout beneficiaries and transfers |
| Collections | `/api/v1/payments/collections` | Mobile money collection and verify |
| Channels | `/api/v1/payments/channels` | Org collection channel policy |
| Capabilities | `/api/v1/payments/capabilities/org` | Payout rails for the organization |

Fluide selects the processor for a rail and corridor. Merchant paths are `payouts`, `collections`, and `checkout-sessions`.

## Configuration

Processor credentials are service environment variables, validated with Joi at bootstrap (`src/config/`).

## Inter-service

- **Kafka** for async transaction processing and inbound webhook fan-out
- Wallets may be provisioned from payroll via Kafka commands
- Internal banking ops: `/api/v1/payments/internal/banking/*` (internal API key)
